System Architecture

RealEstate uses a standard **N-Tier design** separating presentation concerns from business rules and physical database layers. The Web MVC client issues transactions that resolve down services boundaries, using **Repository & Unit of Work abstractions** over Entity Framework Core to isolate SQL Server queries and ensure proper transactions.

Technical Deep-Dive

01. N-Tier Layered Decoupling

Separated the architecture into Presentation, Core Business logic, and Data Access projects. This decoupling ensures database engine migrations (e.g. SQLite to SQL Server) can be made without touching controllers or views.

02. Repository & Unit of Work Patterns

By abstracts EF Core DbContext calls behind a unified **Unit of Work** wrapper, the platform guarantees that transactional processes (such as recording a lease and verifying tenant deposits) succeed or fail together.

03. Cookie & Role Authentication

Implemented claims-based cookie authentication filters native to ASP.NET Core. Users are grouped into Admin / Tenant roles to isolate management endpoints from student client portal views.

04. Database Persistence & Indices

Optimized property queries by implementing clustered indexes on foreign key relationship columns (such as PropertyId on lease records), reducing SQL Server lookup times under database tests.
