System Architecture

OllamaNet is a distributed microservices platform for local LLM inference. An Ocelot API Gateway serves as the single entry point, routing HTTP traffic to four independent .NET 9 services. A shared SQL Server database via Ollama_DB_Layer provides unified persistence, while RabbitMQ handles async event-driven communication between services. .NET Aspire orchestrates the local development stack.

Client → Gateway

All traffic enters through the Ocelot API Gateway. It validates JWT tokens, extracts claims into HTTP headers, and enforces role-based access.

Request Flow — Chat with RAG

A chat request traverses five layers: client → gateway → conversation service → Ollama LLM → streamed response back. When documents are attached, the RAG pipeline intercepts, generates embeddings, and enriches the prompt with retrieved context before inference.

1. Client Request

User sends a prompt (optionally with uploaded documents) to the gateway with a JWT Bearer token.

Data Flow — Events & Caching

Two async patterns power OllamaNet's data layer. RabbitMQ decouples admin operations from runtime configuration via a publish-subscribe model. Redis caches hot paths (model listings, search results, config) with per-domain TTLs to reduce database load.

Technical Deep Dive

01. .NET Aspire Orchestration

The AppHost project wires all services together using Aspire Hosting v9.2.1. Each service gets automatic service discovery, OpenTelemetry instrumentation (OTLP exporter), and HTTP resilience via AddServiceDefaults(). No docker-compose needed for local dev.

02. Ocelot Gateway & Auth

The gateway handles JWT validation, extracts UserId, Email, and Role from claims into X-User-* headers, and enforces role-based access via RoleAuthorizationMiddleware. Routes are split into per-service JSON files with variable substitution.

03. RAG Pipeline

Documents are extracted (PDF via PdfPig, Word via OpenXml), chunked, and embedded using multilingual-e5-large via Ollama. Vectors are stored in Pinecone (doc-index). Retrieval uses 0.7 similarity threshold with top-k 3, injected into the prompt context.

04. SSE Streaming

Chat responses stream via Server-Sent Events. The /chats/stream endpoint uses OllamaSharp to yield tokens as they're generated by the LLM, enabling real-time UI updates without polling or WebSocket overhead.

05. Shared Data Layer

All four services share Ollama_DB_Layer — a class library containing MyDbContext (inheriting IdentityDbContext<ApplicationUser>), entity definitions, repository pattern, and unit of work. Single SQL Server database, consistent migrations.

06. RabbitMQ Event Bus

AdminService publishes inference.url.changed events to the service-discovery exchange. ConversationService consumes from the inference-url-updates queue, dynamically updating its Ollama endpoint without restart. Polly provides circuit breaker + retry resilience.
