System Architecture Overview

Techno Terminal is an isolated Modular Monolith built with FastAPI and SQLModel. It features 11 domain modules, Supabase JWT authentication, and a PostgreSQL database with 21 tables and 20+ analytical views. The architecture follows Router → Service → Repository pattern with clean domain boundaries.

Client Layer

React SPA sends HTTPS requests to the FastAPI backend. Authentication uses Supabase JWT tokens.

Request Flow: Router → Service → Repository

Every HTTP request follows a strict layered flow. Routers handle HTTP concerns only. Services contain business logic and transaction boundaries. Repositories execute pure SQLModel queries. The dependencies.py file manages all DI factories.

HTTP Request

Client sends request with Authorization: Bearer <jwt> header to FastAPI router.

Database Schema: 21 Tables, 20+ Views

The PostgreSQL database features 21 modular tables across 4 domains, 20+ analytical views for reporting, JSONB metadata columns for flexible data, and Alembic migrations for version control. The schema uses soft deletes, partial indexes, and audit timestamps.

Core Domain Tables

Students, Parents, Users, Employees - the foundational entities for all business operations.

Authentication Flow

Authentication uses Supabase JWT tokens validated via HTTPBearer. The system maps Supabase UIDs to local users and enforces role-based access with require_admin and require_system_admin guards. Two simplified roles: admin and system_admin.

JWT Extraction

HTTPBearer dependency extracts JWT from Authorization header and validates format.

Technical Deep-Dive

01. Modular Monolith Architecture

Built as an isolated modular monolith with 11 domain modules. Each module enforces strict boundaries: Routers (HTTP only) → Services (business logic) → Repositories (SQLModel queries). The Two-Layer Schema Rule ensures API DTOs never leak into service layer.

02. Database Design

PostgreSQL instance with 21 tables and 20+ analytical views. Features JSONB metadata columns, soft deletes via deleted_at, partial unique indexes, and 83 Alembic migrations. Connection pool: 10-15 connections with 240s recycle.

03. Authentication & Authorization

Secured with Supabase JWT tokens validated via HTTPBearer. Maps to local users via supabase_uid. Two simplified roles: admin and system_admin. Role guards: require_admin, require_system_admin, require_any.

04. Testing & Reliability

Achieved 94% unit test coverage (161+ tests across 26 modules). Transaction-isolated fixtures with Pytest. Mock JWT credentials for testing. CI pipeline on GitHub Actions with PostgreSQL 15 service container.

05. Dependency Injection

Centralized in dependencies.py with 3 layers: Core (DB/JWT), Role Guards, Service Factories. Two DI patterns: UoW-based (CRM, Finance, HR) and Stateless (Academics, Attendance). Fresh service instances per request.

06. Background Processing

Two async schedulers via FastAPI lifespan: Notification Scheduler (periodic report dispatch) and Task Scheduler (recurring task spawner). Both use independent sessions for non-transactional operations.
